# Java Virtual Machine (JVM) Report

## Introduction

The Java Virtual Machine (JVM) is an abstract computing machine responsible for executing Java bytecode. JVM enables platform independence through the principle of "Write Once, Run Anywhere".

---

# JVM Architecture

## 1. Class Loader

The Class Loader subsystem loads class files into memory when required.

Responsibilities:

* Loading classes
* Linking classes
* Initialization

### Phases

### Loading

Reads .class files and loads them into JVM memory.

### Linking

Consists of:

* Verification
* Preparation
* Resolution

### Initialization

Static variables and static blocks are initialized.

Example:

```java
public class Student {
    static int count = 10;
}
```

---

## 2. Runtime Data Areas

JVM memory is divided into several runtime areas.

### Heap Area

Stores:

* Objects
* Instance variables

Characteristics:

* Shared among all threads
* Managed by Garbage Collector

Example:

```java
Student student = new Student();
```

The object is stored in Heap Memory.

---

### Stack Area

Stores:

* Method calls
* Local variables
* Partial results

Each thread has its own stack.

Example:

```java
public void display() {
    int count = 10;
}
```

Variable count is stored in Stack Memory.

---

### Method Area

Stores:

* Class metadata
* Static variables
* Method information
* Runtime constant pool

Example:

```java
static String collegeName = "ABC College";
```

Stored in Method Area.

---

### Program Counter (PC) Register

Stores address of currently executing instruction.

Characteristics:

* One PC Register per thread
* Helps JVM track execution sequence

---

## 3. Execution Engine

Execution Engine executes bytecode loaded into memory.

Components:

### Interpreter

Reads and executes bytecode instruction by instruction.

Advantages:

* Fast startup

Disadvantages:

* Slower execution for repetitive code

---

### JIT Compiler (Just-In-Time Compiler)

Converts frequently executed bytecode into native machine code.

Advantages:

* Improved performance
* Reduced interpretation overhead

Process:

```text
Java Source Code
        ↓
Bytecode (.class)
        ↓
JVM
        ↓
JIT Compiler
        ↓
Machine Code
```

---

## JIT Compiler vs Interpreter

| Feature      | Interpreter  | JIT Compiler             |
| ------------ | ------------ | ------------------------ |
| Execution    | Line by line | Compiles entire hot code |
| Speed        | Slower       | Faster                   |
| Startup      | Faster       | Slightly slower          |
| Memory Usage | Lower        | Higher                   |
| Performance  | Lower        | Higher                   |

---

## Write Once, Run Anywhere

Java source code is compiled into bytecode.

Example:

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
```

Compilation:

```bash
javac HelloWorld.java
```

Produces:

```text
HelloWorld.class
```

The generated bytecode can run on any platform having a JVM.

Example:

* Windows JVM
* Linux JVM
* macOS JVM

This platform independence is known as:

### Write Once, Run Anywhere (WORA)

---

## JVM Execution Flow

```text
Java Source Code (.java)
            ↓
Compiler (javac)
            ↓
Bytecode (.class)
            ↓
Class Loader
            ↓
Runtime Data Areas
            ↓
Execution Engine
            ↓
Machine Code
```

---

## Conclusion

The JVM provides platform independence, memory management, class loading, and efficient execution through the Class Loader, Runtime Data Areas, and Execution Engine. Features such as JIT Compilation and WORA make Java one of the most portable and widely used programming languages.
